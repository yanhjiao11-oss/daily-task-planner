# 每日任务规划工具

一个纯静态的个人任务规划工具，支持任务紧急度排序、番茄钟、离线缓存，以及通过 GitHub Gist 在多台设备之间同步。

## 本地使用

本项目不需要构建工具或后端服务。直接用浏览器打开 `index.html` 即可，也可以在项目目录启动一个静态服务器：

```bash
npx serve .
```

GitHub Pages 可以直接托管仓库根目录，不需要构建步骤。

## GitHub Gist 同步

1. 打开 GitHub Settings → Developer settings → Personal access tokens。
2. 创建 classic token 时只勾选 `gist` 权限；fine-grained token 只授予 Gists 相关权限。
3. 在应用右上角设置中填入 Token。
4. Gist ID 留空时点击保存，应用会创建一个 Secret Gist，并显示新的 Gist ID。
5. 在第二台设备中填入同一个 Token 和 Gist ID，即可读取相同数据。

数据保存在 Gist 的两个文件中：

- `tasks.json`：任务及累计番茄数据
- `pomodoro-log.json`：完整专注记录

Token 和 Gist ID 只保存在当前浏览器的 `localStorage`。GitHub Token 具有访问能力，请只使用 `gist` 权限的 Token，不要将它写进代码或提交到仓库。

## 离线行为

每次成功同步后，数据会同时写入本地缓存。网络不可用或 GitHub API 失败时，应用仍可继续使用本地数据，并显示“离线 / 未同步”。恢复网络后会自动尝试同步，也可以点击右上角的重试按钮。

## 部署到 GitHub Pages

1. 新建一个 GitHub 仓库。
2. 将 `index.html`、`summary.html`、`styles.css`、`summary.css`、`app.js`、`summary.js` 和 `README.md` 上传到仓库根目录。
3. 打开仓库 Settings → Pages。
4. 在 Build and deployment 中选择 `Deploy from a branch`。
5. 选择 `main` 分支和 `/ (root)` 目录后保存。
6. 等待 GitHub Pages 发布，打开页面提供的 URL。

## 功能说明

- 紧急程度使用具体的时间范围：当日完成、本周完成、长期任务，新任务默认选择“本周完成”。
- 默认智能排序顺序为：已逾期任务 → 创建超过 2 天而自动晋级的本周任务 → 当日任务 → 本周任务 → 长期任务。
- 本周任务创建满 3 个自然日后会自动排到普通当日任务之前，并显示“已自动提升至今日首位”；无截止日期的任务也不会因长期搁置而被忘记。
- 任务支持“待办 → 进行中 → 已完成待客户回复 → 已完成”的完整流转，也可以从卡片下拉框直接切换或回退状态。
- “待客户回复”任务会记录开始等待的时间，继续参加紧急度、逾期和拖延统计，不会过早归档；真正完成后才进入默认折叠的归档区。
- 新建或编辑任务时，也可以直接在“紧急程度”下拉框中选择“待客户回复”；保存后会自动进入待回复状态。
- 任务可以添加“测试”和“关键优化”标签；带标签事项会自动汇总到独立的复盘总结页，并可持续编辑客户名称、测试或优化动作、结果描述。
- 番茄钟支持绑定任务、短休息/长休息、浏览器通知和提示音。
- 每次完整专注会增加任务的番茄数与专注分钟，并写入 `pomodoro-log.json`。

## 长期复盘

1. 在新建或编辑任务时，勾选“测试”“关键优化”中的一个或两个标签。
2. 点击页面右上角的“复盘总结”。
3. 对汇总事项填写客户名称、测试或优化动作、结果描述。
4. 点击该事项的“保存记录”；以后可以继续修改并再次保存。

一个任务即使同时包含两个标签，也只生成一条复盘记录。复盘内容保存在任务自身的数据中，会与任务一起写入 `tasks.json` 并参与 Gist 同步。
